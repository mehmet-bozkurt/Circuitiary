# Interface languages

Turkish is the default language and the source text. English is an optional second language, chosen with the **Dil / Language** picker in the navigation bar, or with `?lang=en` in the address. The choice is saved in `localStorage` (`circuitiary-locale`). The browser's language is not consulted: the app opens in Turkish unless asked otherwise.

The language is one reactive value, `locale` in `src/i18n.ts`. Text reads it at render time, so the picker changes the page in place and no page state (experiment settings, run records, a built circuit) is lost. Addresses (`/ogren/...`), element ids, `data-testid` values, share-link keys and exported file formats are the same in both languages.

## Rules for text

1. **Turkish output does not change.** With the language set to Turkish, every visible string, accessible name and number format is exactly what it was before a string was made bilingual. The existing tests look elements up by their Turkish names.
2. **Component text lives beside the component**, in `Name.messages.ts`:

   ```ts
   import { defineMessages } from '../i18n'
   export const messages = defineMessages({
     tr: { title: 'Sözlük', found: (n: number) => `${n} sözcük bulundu.` },
     en: { title: 'Glossary', found: (n: number) => `${n} words found.` },
   })
   ```

   `defineMessages` makes the type check fail when English lacks a key, has an extra one, or a function takes other parameters. In the component: `const m = useMessages(messages)`, then `{{ m.title }}` in the template and `m.value.title` in script. A whole sentence is one message, with a function for its values, because word order differs between the languages.
3. **Content constants keep their Turkish export and gain an English twin** with the suffix `En` and the same type, in the same module: `guidedSteps` and `guidedStepsEn: typeof guidedSteps`. A consumer chooses at render time: `computed(() => L(guidedSteps, guidedStepsEn))`. Ids, order and array lengths are identical in both.
4. **Functions that return text read the language themselves** with `L(tr, en)` or `pick(messages)`. Their Turkish result is unchanged, so existing callers and tests keep working.
5. **Never choose the language once at module load.** `L(...)`, `pick(...)` and `m.value` are read inside a template, a `computed`, or a function called while rendering. A module-level `const label = L('a', 'b')` freezes the language.
6. **State does not hold finished text.** An error or status line kept in a `ref` is stored as a function, `ref<(() => string) | null>(null)`, set with `status.value = () => m.value.saved(n)` and rendered with `{{ status?.() }}`. A stored string would stay in the language it was written in.
7. **Numbers** go through `decimal()` / `withComma()` (`src/format.ts`): decimal comma in Turkish, decimal point in English. Case conversion and sorting use `localeTag()`.
8. **Translation is faithful.** English says what the Turkish says, with every caveat and limit kept ("model assumption", "not a measurement", "not validated"). No claim is added, strengthened or dropped. Neuron names, dataset names, units, equations and symbols are not translated.

## Checks

- `npm run typecheck`: English has the same shape as Turkish.
- `npm test`: `src/i18n.test.ts` and the content tests (matching ids and lengths of the `En` twins).
- `tests/language.spec.ts` (Playwright): every page is opened in Turkish, switched to English in place and scanned for leftover Turkish text; the choice survives a reload; `?lang=en` works; page state survives the switch.
